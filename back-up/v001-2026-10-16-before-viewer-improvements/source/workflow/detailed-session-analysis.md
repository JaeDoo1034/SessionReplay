# 리플레이 화면 기반 상세 분석

`/viewer`는 최신 세션을 선택해 전체 리플레이를 자동 재생합니다. **상세 분석**을 켜면 재생이 일시정지되며 분석 조건을 선택할 수 있습니다.

1. **전체 세션 / 현재 선택한 세션**을 선택합니다. 기본값은 전체 세션입니다.
2. 재생 위치 슬라이더 또는 **기록된 화면 → 화면으로 이동**으로 원하는 장면을 찾습니다.
3. **이 화면 선택**으로 URL 경로·쿼리·해시 및 기록된 화면 이름을 지정합니다.
4. 선택 사항으로 **화면에서 버튼 선택**을 누르고 리플레이 속 버튼/링크를 클릭합니다. 버튼 내부 아이콘이나 텍스트 클릭도 같은 버튼 조건으로 처리합니다.
5. **실제 로그 확인**은 선택 범위에 조건을 적용하고 실제 기록을 최대 50건 보여줍니다. LLM 호출은 하지 않습니다.
6. **분석 실행**은 기준 설정 → 로그 분석 → LLM 분석을 React Flow 팝업으로 보여줍니다. 완료 결과는 좌측 분석 메뉴에 표시됩니다.

## 분석 의미

- 화면과 버튼 조건을 동시에 충족한 **세션 전체의 행동**을 분석합니다. 클릭 구간만 잘라 분석하지 않습니다.
- 세션 수는 고유 고객 수가 아닙니다.
- 버튼 조건을 생략하면 해당 화면을 방문한 세션을 찾습니다. 최초 스냅샷만 있는 방문도 포함합니다.
- 화면 이름은 `view_state` 로그와 최초 스냅샷의 `.screen.active[data-view]`로 판별합니다. 일반 URL 페이지는 URL 경로·쿼리·해시로 구분합니다. 별도 SPA는 화면 식별 로그를 수집해야 합니다.
- 버튼은 CSS 식별자로 매칭합니다. DOM 구조가 바뀌면 다시 선택해야 할 수 있습니다. 이름만 같은 다른 버튼으로 조건을 확장하지 않습니다.
- 전체 세션은 저장소를 페이지 단위로 끝까지 조회합니다. 조회 실패를 조용히 누락하지 않고 오류로 표시합니다.
- 집계 지표는 모든 일치 세션의 평균이며, LLM에 보내는 개별 행동 요약 예시는 최신 30개 세션까지입니다. 집계 수치와 예시 개수를 구분해 전달합니다.
- 실행 상태는 실제 조회와 API 응답에 연결되어 있습니다. 알 수 없는 LLM 진행률을 임의로 표시하지 않습니다.
- 분석 조건과 결과는 현재 화면에서 유지됩니다. 새로고침 후 영구 저장하지 않습니다.

## 개발 및 검증

기존 Express 서버와 재생기를 유지하고, 상세 분석 패널만 React로 마운트합니다. React Flow 사용자 정의 노드와 연결선은 `ReactFlow_Ref/langgraph-flow-monitor`를 참고했습니다.

```sh
npm install
npm run build      # web/replay-detail → web/replay-viewer/detail-flow.js, .css
npm run dev        # .env에 설정된 실제 저장소, 기본 포트 4173
npm test           # 필터링·범위·페이지 조회 테스트
```

별도 샘플 DB로 검토하려면:

```sh
npm run preview:detail  # http://localhost:4174/viewer
npm run test:viewer    # 샘플 DB 기준 Chrome 브라우저 검증; LLM 오류는 테스트 응답
npm run test:viewer -- --live # 실제 OpenAI 호출과 결과 표시 확인
```

샘플 DB는 OS 임시 폴더의 `session-replay-detail-preview.sqlite`이며 세션 이름에 `[샘플]`이 붙습니다. 기존 DB와 분리됩니다. 실제 LLM 검증에는 기존 `.env`의 키를 사용합니다. `CHROME_PATH`로 Chrome 실행 경로, `PREVIEW_URL`로 검증 서버 주소, `SCREENSHOT_DIR`로 검증 캡처 경로를 지정할 수 있습니다.
