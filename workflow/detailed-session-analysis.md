# 리플레이 화면 기반 상세 분석

`/viewer`는 최신 세션을 선택해 첫 화면만 표시하며 자동 재생하지 않습니다. 좌측 패널 우측 상단의 `Play ON` 버튼을 누르면 재생되고, `Play OFF` 버튼을 누르면 일시정지됩니다. 다시 누르면 멈춘 위치부터 이어 재생합니다. `Mutation ON/OFF`도 같은 위치에 배치합니다. **상세 분석**을 켜면 재생이 일시정지되며 분석 조건을 선택할 수 있습니다.

1. **전체 세션 / 현재 선택한 세션**을 선택합니다. 기본값은 전체 세션입니다.
2. 재생 위치 슬라이더 또는 **기록된 화면 → 화면으로 이동**으로 원하는 장면을 찾습니다.
3. **이 화면 선택**으로 URL 경로·쿼리·해시 및 기록된 화면 이름을 지정합니다.
4. 선택 사항으로 **화면에서 버튼 선택**을 누르고 리플레이 속 버튼/링크를 클릭합니다. 버튼 내부 아이콘이나 텍스트 클릭도 같은 버튼 조건으로 처리합니다.
5. **실제 로그 확인**은 선택 범위에 조건을 적용하고 실제 기록을 최대 50건 보여줍니다. LLM 호출은 하지 않습니다.
6. **분석 실행**은 기준 설정 → 로그 분석 → LLM 분석을 React Flow 팝업으로 보여줍니다. 완료 결과는 좌측 분석 메뉴에 표시됩니다.

## 분석 의미

- 화면과 버튼 조건을 동시에 충족한 **세션 전체의 행동**을 분석합니다. 클릭 구간만 잘라 분석하지 않습니다.
- 세션 수는 고유 고객 수가 아닙니다.
- 버튼 조건을 생략하면 해당 화면을 방문한 세션을 찾습니다. 최초 스냅샷만 있는 방문도 포함합니다.
- 화면 이름은 `view_state` 로그와 최초 스냅샷의 `.screen.active[data-view]`로 판별합니다. 일반 URL 페이지는 URL 경로·쿼리·해시로 구분합니다. 별도 SPA는 화면 식별 로그를 수집해야 합니다.
- 버튼은 CSS 식별자로 매칭합니다. DOM 구조가 바뀌면 다시 선택해야 할 수 있습니다. 이름만 같은 다른 버튼으로 조건을 확장하지 않습니다.
- 전체 세션은 저장소를 페이지 단위로 끝까지 조회합니다. 조회 실패를 조용히 누락하지 않고 오류로 표시합니다.
- 집계 지표는 모든 일치 세션의 평균이며, LLM에 보내는 개별 행동 요약 예시는 최신 30개 세션까지입니다. 집계 수치와 예시 개수를 구분해 전달합니다.
- 실행 상태는 실제 조회와 API 응답에 연결되어 있습니다. 알 수 없는 LLM 진행률을 임의로 표시하지 않습니다.
- 분석 조건과 결과는 현재 화면에서 유지됩니다. 새로고침 후 영구 저장하지 않습니다.

## 개발 및 검증

기존 Express 서버와 재생기를 유지하고, 상세 분석 패널만 React로 마운트합니다. React Flow 사용자 정의 노드와 연결선은 `ReactFlow_Ref/langgraph-flow-monitor`를 참고했습니다.

```sh
npm install
npm run build      # web/replay-detail → web/replay-viewer/detail-flow.js, .css
npm run dev        # .env에 설정된 실제 저장소, 기본 포트 4173
npm test           # 필터링·범위·페이지 조회 테스트
```

별도 샘플 DB로 검토하려면:

```sh
npm run preview:detail  # http://localhost:4174/viewer
npm run test:viewer    # 샘플 DB 기준 Chrome 브라우저 검증; LLM 오류는 테스트 응답
npm run test:viewer -- --live # 실제 OpenAI 호출과 결과 표시 확인
```

샘플 DB는 OS 임시 폴더의 `session-replay-detail-preview.sqlite`이며 세션 이름에 `[샘플]`이 붙습니다. 기존 DB와 분리됩니다. 실제 LLM 검증에는 기존 `.env`의 키를 사용합니다. `CHROME_PATH`로 Chrome 실행 경로, `PREVIEW_URL`로 검증 서버 주소, `SCREENSHOT_DIR`로 검증 캡처 경로를 지정할 수 있습니다.

## 2026-10-16: 4분할 작업 화면

화면은 상단 전체 폭의 업무 진행 영역과 하단 3개 열로 구성됩니다.

- **상단**: 기준 설정 → 로그 분석 → LLM 분석 순서, 현재 상태와 조건 요약을 표시합니다. 상세보기로 기존 React Flow 팝업을 열 수 있습니다. 분석 실행이 팝업을 강제로 열지는 않습니다.
- **좌측**: 세션 리플레이, 재생 제어, 위치 이동.
- **가운데 상단**: 분석 범위와 화면·버튼 조건 설정, 분석 실행.
- **가운데 하단**: SDK 수집 로직으로 생성한 로그 구조. 저장된 이벤트에서 샘플을 가져오지 않습니다. 이벤트 순번·시각·클릭 좌표 등 실행 시 결정되는 값은 자리표시자로 표시합니다.
- **우측**: 현재 세션 요약 및 실행 완료된 조건별 고객군 분석 결과.

`SessionReplaySDK.previewCollection()`은 실제 `handleClick()`·`track()`·`record()`와 같은 데이터 생성 함수를 사용합니다. 수집 정책의 마스킹·차단 및 이벤트 활성화 설정을 반영하며, 녹화 시작·큐 추가·이벤트 전송을 하지 않습니다. 버튼 선택에 사용되는 DOM이 iframe 안에 있어도 올바른 문서를 기준으로 식별자를 생성합니다.

가운데 **조건 일치 확인**은 실제 저장소에서 조건에 맞는 세션을 확인하는 명시적 실행 동작입니다. 그 집계는 상단 단계에 표시되며, 실제 일치 로그는 상세보기 팝업에서 확인할 수 있습니다. 가운데 로그 구조 영역은 계속 로직 기반 미리보기를 유지합니다.

데스크톱의 하단 각 열은 내용이 길면 독립적으로 스크롤됩니다. 화면 너비 820px 이하에서는 리플레이 → 조건 및 로그 구조 → 결과 순서로 세로 배치됩니다. 이전 소스는 `back-up/v001-2026-10-16-before-viewer-improvements/source`에 보존되어 있습니다.

### 리플레이 표시 배율

리플레이는 원본 뷰포트 유지형 자동 축소를 사용합니다. iframe의 너비·높이는 녹화 당시 값으로 유지하고 표시 배율만 `min(영역 내부 너비 / 원본 너비, 영역 내부 높이 / 원본 높이, 1)`로 계산합니다. 패딩을 제외한 가용 영역에 원본 뷰포트 전체를 가운데 정렬합니다. 가로 여백을 잘라내거나 원본보다 확대하지 않습니다. `ResizeObserver`로 재생 영역 크기 변화를 감지해 배율을 갱신하며 히트맵에도 같은 배율을 적용합니다.

### 상세 분석 OFF 및 복수 조건

- OFF: 현재 선택한 세션 1개의 체류 시간·클릭·입력·제출, 행동 유형 요약, 화면 탐색 흐름을 가운데에 표시합니다. ‘선택 세션 정밀 분석’은 화면 조건 없이 해당 세션 전체만 분석합니다. OFF로 돌아오면 우측에도 현재 세션의 기본 요약을 복원합니다.
- ON: ‘화면 조건 보기’ 목록에서 체크하면 화면을 조건에 추가하면서 리플레이도 그 화면으로 이동합니다. ‘보기’는 조건을 바꾸지 않고 해당 화면만 표시합니다.
- 여러 화면을 선택하고 화면별로 버튼을 여러 개 추가할 수 있습니다. ‘화면에서 버튼 복수 선택’을 누른 뒤 버튼을 계속 선택하고 ‘버튼 선택 완료’로 마칩니다. 같은 버튼을 다시 클릭하거나 목록의 ×로 해제합니다. 화면을 해제하면 그 화면의 버튼 조건도 제거합니다.
- 선택 목록의 버튼 번호를 리플레이 내부의 테두리·번호와 함께 표시합니다. 다른 화면으로 이동했다가 돌아와도 선택 표시를 복원합니다.
- 각 화면 안의 버튼 조건은 OR이며, 화면 간 조건도 OR입니다. 예: (상품몰에서 상담 버튼 A 또는 B 클릭) 또는 (이체 화면 방문). 버튼이 없는 화면은 방문 조건으로 취급합니다. 동일 이벤트가 여러 조건과 겹쳐도 한 번만 집계합니다.
- 상세 분석 API는 `conditions: [{pagePath, screenName, screenLabel, buttons: [{label, selectors}]}]`를 받습니다. 기존 단일 화면·버튼 요청도 지원합니다. OFF는 `{mode: "session", scope: "current", sessionId}`를 사용합니다. 빈 상세 조건은 전체 세션 분석으로 우회하지 않고 오류를 반환합니다.
- 제한: 화면 최대 30개, 화면당 버튼 최대 50개. 조건·번호·결과는 현재 화면 상태이며 세션을 바꾸면 선택을 초기화합니다.
